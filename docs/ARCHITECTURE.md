# AJACKTI Agent Harness Architecture (`docs/ARCHITECTURE.md`)

`ajackti-agent-harness` is designed around five principles: a lightweight `AGENTS.md` entrypoint, the repository as the single source of authority, progressive context discovery, evidence-based completion, and repo-native validation in the consumer repository.

## 1. Three-Layer Composition

1. **Core Layer (`core/`)**:
   - Defined in [../core/policy.json](../core/policy.json) and [../AGENTS.md](../AGENTS.md).
   - Pins the `external-first` policy with coordinator-owned workflow, context, and quota-aware model selectors (`execution_model.workflow_selection`, `execution_model.model_selection`, `worker_validation`, and `devin_worker_validation`, validated by [../scripts/workflow_policy.py](../scripts/workflow_policy.py) and [../scripts/model_policy.py](../scripts/model_policy.py)): `WORKFLOW_WORKER=agy|devin` (unset/empty defaults to `agy`; `execution_model.worker_cli` is the legacy `"agy"` binary/default while `execution_model.workflow_selection` chooses the worker and `reviewer_worker: "agy"` keeps all reviewers on `agy`), `WORKFLOW_CONTEXT=lean|compact|full` (unset/empty defaults to `lean`, the installed runner candidate default; `compact` and `full` are retained), and `AGY_MODEL=claude-opus-5-5-high|gemini-4-argon-high` (unset/empty defaults to `gemini-4-argon-high`). All selectors enforce `exact_match_only: true`, and invalid values `BLOCK` before external calls.
   - **Coordinator-owned preflight & quota**: before each task the coordinator refreshes native `quota`, `auth`, and `availability` (`agy --print /usage` queries backend quota, records actual reported usage via `record_actual_query_usage: true`, and avoids redundant model probes because a zero-tool probe proves `availability_only`), prefers `claude-opus-5-5-high` while quota is available (otherwise verified `gemini-4-argon-high`), and selects `devin` **only** from actual recent successful generation (`devin_requires_recent_successful_generation: true`), never claimed numeric quota (`claim_numeric_devin_quota: false`; `opencode` has `opencode_role: "probe_only"`). The harness performs no transparent hooks, runtime quota polling (`runtime_quota_polling: false`), account/key/billing rotation, or automatic failover (`automatic_failover: false`).
   - **Worker/reviewer role split & Devin `lean` schema rules**:
     - **`agy` reviewers and `agy` workers (`agy_workers_and_all_reviewers`)**: all fresh reviewers remain `agy` pinned to the selected `AGY_MODEL` with `--effort high` in `request-review` mode, and only `agy` workers share those metadata requirements (`worker_validation`: exit code `0`, exact `init.model` match, explicit `init.permission_mode == "request-review"` where missing permission metadata is `BLOCKED`, `init.effort == "high"` when present or recorded `--effort high` flag evidence plus `-high` slug, `result.status == "SUCCESS"`, nonempty response, and no permission denial).
     - **Devin worker (`devin_worker_validation`, `swe-1-6-slow`)**: tool-free generator in an isolated cwd (`require_isolated_cwd: true`), `permission_config: "deny_all"` + unconditional `PreToolUse` exit `2` (`pre_tool_use_hook: "unconditional_exit_2"`), CLI `auto` / `ATIF-v1.7` `"Normal"` proof mode, `0` tool calls/observations (`max_tool_calls: 0`, `max_observations: 0`), fresh session per attempt (`require_fresh_session_per_attempt: true`), no `high`-effort or `request-review` claim, and no fabricated `agy` proof. `strict_json_files` replacements (`exact_scoped_replacements_only`, exact final response/stdout match allowing at most `1` leading `ESC[?2004l` and `1` trailing newline) are validated before mechanical apply with precondition hashes and atomic rollback (no deletions, symlinks, path aliases, or command execution).
     - **Devin `lean` (`devin_lean_only`)**: `lean` uses the `compact` prompt (`lean_uses_compact_prompt: true`) plus per-session Devin `disabled_tools` (`lean_require_per_session_disabled_tools: true`) and requires ATIF `agent.tool_definitions` to be a `well_formed_unique_name_nonempty_subset` of `mcp_call_tool`, `mcp_list_servers`, `mcp_list_tools`, `mcp_read_resource`, `skill` (`lean_block_invalid_tool_definitions_before_apply: true`, `claim_lean_tool_schema_checks_for_agy_or_non_lean: false`). Schema hiding is not authorization (`schema_hiding_authorizes_tools: false`); all five tools remain denied by config and unconditional `PreToolUse` exit `2`.
     - **Delegated runtime enforcement, usage & triage**: this repository delegates live Devin cwd isolation, context/schema proof validation, and mechanical replacement application to the installed runner (`runtime_context_and_proof_owner: "upstream_runner"`); declarative policy and file prerequisites in this repo are not live generation, measured token savings, or globally proven security (no live Devin generation or benchmarking was performed by this repo's offline test suite). Usage totals are tracked separately (`usage_totals.devin` vs `usage_totals.gemini`). Evidence triage uses `jev-1.13.0` (`jev-pool`, no file edits). Optional RTK filtering applies only to passing supported `pytest` logs with equal raw and filtered pass counts; raw exits/counts and full reviewer evidence remain authoritative, and `unittest` is unchanged.
   - **Retry ledger (coordinator-owned)**: at most `2` extra worker executions per task, shared across internal reworks and every cross-run, model, worker, or context restart (`shares_task_retry_ledger: true`) and never reset on model, worker, context, or auth changes. Model mismatch and permission denial are terminal; only `quota_error`, `auth_error`, or `availability_error` permit reassessment (never via account/key/billing changes). Before any restart the coordinator reserves one execution, stops if none remain, passes the remaining budget as `--max-reworks` (`0..2`, default `2`), preserves the original snapshot, reviews aggregate changes across all executions, and discloses partial edits. `harness.py run` accepts an optional `--max-reworks` override (`0..2`, default `2`) and does **not** compute or enforce the ledger.
   - Requires passing `--no-resume-worker` and `--context-mode <lean|compact|full>` to the underlying workflow (`antigravity-task-runner/scripts/run_workflow.py`) — note that these are underlying workflow flags, **not** direct `agy` CLI flags or reviewer-session flags (`agy` documents `--conversation` rather than `--resume`). `compact` (and the `lean` prompt) trims `prompt_boilerplate` only (`compact_preserves_verbatim_contract: true`, `compact_preserves_full_scoped_source: true`, `lean_preserves_verbatim_contract: true`, `lean_preserves_full_scoped_source: true`; never minify source to fit packet limits). A fresh context on the same selected model is **independent**, **not stronger** (`independent_not_stronger`), and distinct worker/reviewer provider or model labels (`swe-1-6-slow`, `claude-opus-5-5-high`, `gemini-4-argon-high`) do not prove stronger review.
2. **Domain Profile Layer (`<domain>/profile.json`)**:
   - Explicitly registered in [../harness.json](../harness.json).
   - Includes 10 profiles: `backend/typescript`, `backend/golang`, `backend/rust`, `frontend`, `dashboard`, `ios`, `android`, `quant`, `devops`, `data` (supporting both canonical IDs and aliases for lookup and CLI execution).
   - Supports conceptual inheritance via `extends`: specifically, `dashboard` extends `frontend` (`"extends": ["frontend"]`), adding verification requirements for tabular data, filter state, timezone handling, and role-based access control (`RBAC`).
   - **Effective minimum reviewers (`min_reviewers`)**: for `task`, the minimum reviewer count is computed as the **maximum (`max`)** across the core policy (`core/policy.json`) and all selected profiles plus their inheritance chain (`extends` / `lineage`). The current default is `1`; the installed review gate (`jev_review_gate.py`) supports a range of `1..4`, and any configuration requesting outside `1..4` is `BLOCKED`.
   - **Important note**: A profile provides guidance and capability requirements only, **not proof** that example commands will work in an arbitrary application. Every suggested command in `candidate_checks` carries `"status": "example_unverified"` and `"requires_consumer_acceptance": true`, and is never automatically injected or executed during `run`.
3. **Consumer Repository Context Layer (`repo-context.json` & `task.md`)**:
   - Initialized from [../templates/repo-context.json](../templates/repo-context.json) and [../templates/task.md](../templates/task.md).
   - **`repo-context.json` is advisory only (`advisory_only`)**: `harness.py run` does not read this file as execution authorization (`execution_authorization: false`) or as a source of commands to run. The `run` command accepts and is governed exclusively by explicit CLI arguments (`--workspace`, `--packet`, `--scope`, `--verify-cmd`, `--output-dir`, `--profile`, `--work-kind`, ...).
   - **Packet Contract & Size Limits**: the `--packet` file must be UTF-8 `<= 8000` characters, free of `<UNRESOLVED:...>` or other placeholders, and contain unique unindented header lines: `TASK:`, `WORK_KIND: task`, `QUANT_SEAM: false`. Separate from the `8000`-character user packet threshold, the installed review gate caps the **focused diff at `12000` characters** and the **internal review packet at `20000` characters**; tasks should therefore be decomposed with a narrow `--scope` rather than weakening gates or compressing source code.

## 2. `task` vs `quant` Seam Separation

- **General Engineering Seam (`--work-kind task`)**:
   - Routes to `antigravity-task-runner` (`scripts/run_workflow.py` under `~/.agents/skills`).
   - Applies to `backend/*`, `frontend`, `dashboard` (pure UI/presentation with no financial logic), `ios`, `android`, `devops`, and `data` (pure ETL/schema with no financial calculations).
- **Quantitative Seam (`--work-kind quant`)**:
   - Routes to `antigravity-sol-quant-runner`.
   - The `quant` profile and `--work-kind quant` must be selected whenever a task touches PnL formulas, funding rates, liquidation, slippage, leverage/margin, backtests, or risk management — even when the task lives in the [../dashboard/README.md](../dashboard/README.md) UI or the [../data/README.md](../data/README.md) pipeline.
   - No automatic classifier may move a `quant` seam to `task`. The keyword scan on the `TASK:` line in [../scripts/run_contract.py](../scripts/run_contract.py) is only a supplemental conservative heuristic; **responsibility for semantic seam classification remains with the coordinator**.
   - Currently, `quant` execution via the CLI returns `BLOCKED` (non-zero exit code) because the user requires a reviewer **proven stronger than the selected worker model**, while the current runner only provides fresh `agy` reviewers on the selected `AGY_MODEL` (independent, not stronger). Selecting `claude-opus-5-5-high` or pairing distinct worker/reviewer provider or model labels (including Devin `swe-1-6-slow` and `agy` `claude-opus-5-5-high` / `gemini-4-argon-high`) does not prove a stronger reviewer or unblock `quant`. Unlocking this in the future requires implementing/integrating a separate, approved `quant` execution path together with stronger-reviewer evidence, tests, and explicit user approval, **not merely enabling the `execution_enabled` flag** in [../core/policy.json](../core/policy.json).

## 3. Thin Adapter Design ([../scripts/harness.py](../scripts/harness.py), [../scripts/run_contract.py](../scripts/run_contract.py), [../scripts/run_adapter.py](../scripts/run_adapter.py), [../scripts/workflow_policy.py](../scripts/workflow_policy.py), [../scripts/model_policy.py](../scripts/model_policy.py))

- Requires **Python `>= 3.11`**, is written entirely with the Python standard library (`stdlib`) with no external package dependencies, and is tested by [../tests/test_harness.py](../tests/test_harness.py), [../tests/test_run_contract.py](../tests/test_run_contract.py), and [../tests/test_run_adapter.py](../tests/test_run_adapter.py).
- The offline commands `list`, `show`, `validate`, and `doctor` all support the `--json` flag (`doctor` additionally supports `--skills-root PATH` and a repeatable `--profile PROFILE` flag; the global `--repo-root PATH` flag goes before the subcommand name). `doctor` reports baseline `agy` tooling diagnostics only (`agy`, `jev-pool`, runner paths) and is not proof of Devin readiness/availability (`task_execution_ready` does not authorize `WORKFLOW_WORKER=devin`).
- Does not vendor or rewrite the orchestration/safety-gate logic of `antigravity-task-runner` (or Devin runtime isolation, ATIF proof validation, and replacement application owned by `upstream_runner`), and does not claim that the skills in `~/.agents/skills` are bundled in this repository or that declarative policy/prerequisite checks prove live Devin generation or security.
- Strictly validates the input contract before invoking the runner:
   - `--scope`: accepts only a list of individual relative **file** paths inside `--workspace`; directories, absolute paths, directory traversal (`..`), traversal through symlinks, or touching `.git`, `.env*`, `secrets/`, `credentials/`, secret keys, and protected configuration files (`harness_protected_files`) are forbidden.
   - `--output-dir`: must be a **new, not-yet-existing** directory path (not a symlink), located **outside** the consumer repository's `--workspace`, whose direct parent directory already exists and is writable/traversable (`W_OK | X_OK`).
   - `--dry-run`: runs fully offline (does not look up `agy`/`devin`/`jev-pool` on `PATH` and spawns no subprocesses), but **still requires** the safe non-symlink runner script `antigravity-task-runner/scripts/run_workflow.py` under `--skills-root` (plus safe non-symlink sibling scripts `devin_worker.py` and `jev_review_gate.py` when `WORKFLOW_WORKER=devin`) plus valid `--workspace`, `--packet`, `--scope`, and `--output-dir`; a real run (without `--dry-run`) always checks execute permission (`X_OK`) for `agy` (reviewers) and `jev-pool`, and additionally checks `devin` when `WORKFLOW_WORKER=devin`.
   - Displays commands with `shlex.join` and executes the `argv` list with `shell=False`.
