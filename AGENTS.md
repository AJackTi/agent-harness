# AGENTS.md — AJACKTI Agent Harness Entrypoint

This repository is the single source of authority for AJACKTI's multi-domain agent orchestration configuration. Documentation uses concise English, and technical identifiers remain in English.

## 1. Nonnegotiable Policy

1. **External-First (`WORKFLOW_WORKER=agy|devin`)**:
   - All implementation work (features, fixes, tests, docs, config) must be dispatched first to the external worker (`WORKFLOW_WORKER=agy|devin`, unset/empty `agy`). `execution_model.worker_cli` (`"agy"`) is the legacy `agy` binary/default; `execution_model.workflow_selection` chooses the actual worker, and `agy` is always the reviewer (`reviewer_worker: "agy"`).
   - ChatGPT acts strictly as coordinator (`coordinate`) and final reviewer (`final-review`); local fallback or internal coding is strictly forbidden. No local implementation exception is granted; only mechanical application of proof-validated Devin replacement bytes is permitted.
2. **One Runner per Seam**:
   - `antigravity-task-runner`: used for general engineering tasks (`--work-kind task`).
   - `antigravity-sol-quant-runner`: used for financial math, backtests, PnL, funding, liquidation, and risk (`--work-kind quant`).
   - No automatic classifier may override a quantitative (`quant`) seam into `task`. Any `dashboard` or `data` task involving PnL/funding/liquidation/risk must explicitly select the `quant` profile and `--work-kind quant`.
3. **Worker, Context & Quota-Aware Model Policy** (coordinator-owned; see `execution_model.workflow_selection`, `execution_model.model_selection`, `worker_validation`, and `devin_worker_validation` in [core/policy.json](core/policy.json), [scripts/workflow_policy.py](scripts/workflow_policy.py), and [scripts/model_policy.py](scripts/model_policy.py)):
   - **Selectors**: `WORKFLOW_WORKER=agy|devin` (unset/empty `agy`), `WORKFLOW_CONTEXT=lean|compact|full` (unset/empty `lean`, the installed runner candidate default), and `AGY_MODEL=claude-opus-5-5-high|gemini-4-argon-high` (prefer `claude-opus-5-5-high` while quota is available, otherwise verified `gemini-4-argon-high`; unset/empty defaults to `gemini-4-argon-high`). Exact match only; invalid values `BLOCK` before external calls.
   - **Preflight & Quota**: Before **each** new task, refresh native quota, auth, and availability. `agy --print /usage` queries backend quota; record actual reported usage and avoid redundant model probes (a zero-tool probe proves availability only). Select `devin` only from actual recent successful generation (`devin_requires_recent_successful_generation`), never claimed numeric quota (`claim_numeric_devin_quota: false`). OpenCode is probe-only (`opencode_role: "probe_only"`). No transparent hooks, runtime quota polling, account/key/billing rotation, or automatic failover. Always pass `--no-resume-worker` and `--context-mode` to `run_workflow.py` (`agy` documents `--conversation` rather than `--resume`).
   - **`agy` Reviewers & Workers (`agy_workers_and_all_reviewers`)**: All fresh reviewers remain `agy` on the selected `AGY_MODEL` with `--effort high` in `request-review` mode. Only `agy` workers share those metadata requirements: exit code `0`, exact `init.model` match, explicit `init.permission_mode == "request-review"` (missing field is `BLOCKED`), `result.status == "SUCCESS"`, nonempty response, no denial, and `init.effort == "high"` when present (or `--effort high` flag evidence plus `-high` slug).
   - **Devin Worker (`swe-1-6-slow`) & `lean` Schema Rules**: Tool-free generator in an isolated cwd (`require_isolated_cwd`), `deny_all` config + unconditional `PreToolUse` exit `2`, CLI `auto` / `ATIF-v1.7` `"Normal"` proof mode, `0` tool calls/observations, fresh sessions, no `high`/`request-review` claim, and no fabricated `agy` proof. Strict JSON file replacements (`strict_json_files`, `exact_scoped_replacements_only`, exact final response/stdout match allowing at most one leading `ESC[?2004l` and one trailing newline) are validated then mechanically applied with precondition hashes and atomic rollback (no deletions, symlinks, path aliases, or command execution).
   - **Devin `lean` (`devin_lean_only`)**: `lean` uses the `compact` prompt (`lean_uses_compact_prompt`) plus per-session Devin `disabled_tools` (`lean_require_per_session_disabled_tools`) and requires ATIF `agent.tool_definitions` to be a well-formed, unique-name, nonempty subset (`well_formed_unique_name_nonempty_subset`) of `mcp_call_tool`, `mcp_list_servers`, `mcp_list_tools`, `mcp_read_resource`, `skill`. Missing/extra/duplicate/malformed definitions `BLOCK` before apply. Schema hiding is not authorization (`schema_hiding_authorizes_tools: false`); all five tools remain denied by config and unconditional `PreToolUse` exit `2`. `compact` and `full` are retained; `lean` schema rules apply to Devin `lean` only (`claim_lean_tool_schema_checks_for_agy_or_non_lean: false`), not `agy` reviewers. Separate usage totals (`usage_totals.devin` vs `usage_totals.gemini`). Runtime context/proof enforcement belongs to `upstream_runner`; this repo's offline suite performed no live Devin generation or benchmarking (do not claim runtime availability, measured token savings, or globally proven security).
   - **Context & RTK**: `compact` (and `lean` prompt) trims boilerplate only (`compact_trims_only: "prompt_boilerplate"`), preserving the verbatim contract and full scoped source; never minify source to fit packet limits. Optional RTK filtering applies only to passing supported `pytest` logs with equal raw/filtered pass counts; raw exits/counts and full reviewer evidence are authoritative, and `unittest` is unchanged.
   - **Fail-closed (`BLOCKED`)**: Every error is `BLOCKED`. Model mismatch and permission denial are terminal; only quota/auth/availability blocks permit reassessment.
4. **Standard Pipeline Sequence**:
   - `external_worker` (`agy` or `devin`) -> repo-native `mechanical checks` (tests, scope, `git diff --check` whitespace) -> `Jev` (`jev-1.13.0` via `jev-pool`, `typed evidence/uncertainty triage only`, strictly no file edits) -> `fresh pinned reviewer` (`agy`, minimum `1` for `task`, minimum `2` for `quant`) -> rework rounds bounded by the retry ledger (`--max-reworks` `0..2`) -> `ChatGPT final review`.
   - A `fresh same-model context` is **independent**, **not stronger**.
   - **Task-wide retry ledger** (coordinator-tracked; `pipeline.retry_policy`, `shares_task_retry_ledger: true`): at most `2` extra worker executions per task, shared across internal reworks and every cross-run, model, worker, or context restart; it never resets. Subtract consumed reworks, reserve one execution before any restart, STOP if none remain, and pass the remaining budget as `--max-reworks` (`0..2`, default `2`). Preserve the original snapshot, review aggregate changes across all executions, and disclose partial edits.
5. **Protected Boundaries**:
   - Do not modify credentials, endpoints, live configs, leverage, margin, or safety gates without explicit user approval.
   - The output directory (`--output-dir`) must reside outside the consumer repository workspace to avoid polluting the snapshot.
6. **Quant-Specific Rules (Currently `BLOCKED`)**:
   - `quant` work requires causal provenance, realistic friction, `LONG`/`SHORT` parity, deterministic seeds/tests, and a **stronger reviewer**.
   - Currently, `run --work-kind quant` returns `BLOCKED` (non-zero exit code) because the existing runner cannot yet prove a reviewer stronger than the selected worker model. Distinct worker/reviewer model names (`swe-1-6-slow`, `claude-opus-5-5-high`, `gemini-4-argon-high`) do not prove stronger review; unblocking requires a proven stronger reviewer and explicit user approval. See details in [quant/AGENTS.md](quant/AGENTS.md).
7. **Global Superpowers & Playwright MCP**:
   - At each new task, use the installed `using-superpowers` skill (`v7.0.1` at `/Users/ajackti/.codex/plugins/cache/openai-curated-remote/superpowers/7.0.1/skills/using-superpowers/SKILL.md`, or `$HOME/.codex/plugins/cache/openai-curated-remote/superpowers/7.0.1/skills/using-superpowers/SKILL.md`) and relevant skills; no reinstall or config edits. Local/Solo/internal-coding-agent defaults yield to external-first; repo rules govern commands, financial limits, approvals, and data-sharing (if delegation conflicts, `BLOCK` instead of local coding).
   - Prefer official Microsoft Playwright MCP for relevant browser/UI work, never gratuitous browser automation. Report missing skill/MCP or startup failure honestly; newly configured MCP tools require a session restart. Do not claim perfect instruction enforcement or forced hooks; no permission loosening or account/billing changes.
8. **Result Reporting**:
   - Always report: `verdict`, `actual_model`, `worker_provider`, `worker_model`, `reviewer_model`, `context_mode`, `files`, `actual_check_exit_codes`, separate `usage_totals.devin` vs `usage_totals.gemini`, `confidence < 100%`, and `residual_uncertainty`.
